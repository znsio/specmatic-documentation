# Configure gRPC with Protobuf

Use `runOptions.protobuf` to mock or test a `.proto` contract. These V3 examples were checked with **Enterprise 1.28.3**. They use a local, plaintext unary RPC; streaming, TLS, remote sources and multiple-spec setups need separate guidance.

## Save the inputs

Follow the [Enterprise Docker setup](/references/configuration/local-openapi#docker-setup) and configure your [license](/enterprise_onboarding/license_key). Use one directory and run commands there. Ports **9100**, **9101** and **9102** must be free. The optional demo service needs Node 20+; checking the mock uses [grpcurl](https://github.com/fullstorydev/grpcurl) (checked with 1.9.1).

Save these files, including the example subdirectory:

<CodeBlock language="protobuf" title="greeter.proto">{require('./includes/grpc/greeter.proto?raw').trimEnd()}</CodeBlock>
<CodeBlock language="json" title="greeter_examples/hello.json">{require('./includes/grpc/greeter_examples/hello.json?raw').trimEnd()}</CodeBlock>

The example names the RPC, request and exact response. With no explicit example directories, gRPC looks beside the proto in `greeter_examples`.

The configs explicitly select `protocVersion: '3.23.4'`. Compilation may download the compiler on first use. The release default, `3.11.4`, failed on the tested Apple Silicon machine with `Unsupported platform`; the explicit version is the checked recovery. It is a compiler version, not the Specmatic release or config format version.

These checks establish local unary calls and one same-folder import layout, not nested/remote imports or every compiler version.
