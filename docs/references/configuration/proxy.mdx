# Configure an HTTP proxy

Forward HTTP requests to a running service and save observed interactions as an OpenAPI contract and examples. These V3 examples were checked with **OSS 2.55.3** and **Enterprise 1.28.3**.

**Recording limitation:** `ignoreHeaders: [X-Trace]` did not remove that response header from saved examples in either release. Use nonsensitive traffic for this demo. Do not rely on that field to redact recordings; disable recording when the traffic must not be saved.

## Save the config and start a target

Follow the [Enterprise Docker setup](/references/configuration/local-openapi#docker-setup). Use a fresh directory and run commands there. Ports **19110**, **19111** and **19112** must be free. The optional local target needs Node 20+. Use new output directories: generated contracts/examples can replace or extend files there.

## Start the proxy and send a request

In the original terminal:

<CodeBlock language="shell">{require('./includes/proxy/proxy.sh?raw').trimEnd()}</CodeBlock>
<CodeBlock language="terminaloutput">{require('./includes/proxy/proxy.terminaloutput?raw').trimEnd()}</CodeBlock>

In another terminal, call the **proxy** on 19111:

<CodeBlock language="shell">{require('./includes/proxy/request.sh?raw').trimEnd()}</CodeBlock>
<CodeBlock language="terminaloutput">{require('./includes/proxy/request.terminaloutput?raw').trimEnd()}</CodeBlock>

The target receives the request on 19110. The proxy returns its response, including the demo `X-Trace` and `X-Keep` headers.

Save recordings while the proxy is running:

<CodeBlock language="shell">{require('./includes/proxy/dump.sh?raw').trimEnd()}</CodeBlock>
<CodeBlock language="terminaloutput">{require('./includes/proxy/dump.terminaloutput?raw').trimEnd()}</CodeBlock>

The dump request returns **202** and generation runs in the background. The checked example waits for actual files and inspects their contents; the response alone does not prove that files were written.

Under `recordings`, this exchange produces:

- `proxy_generated.yaml`: a contract inferred from observed traffic.
- `proxy_generated_examples`: JSON request/response examples.

The example contains GET `/greeting`, status 200 and the exact response body. The saved response still contains `X-Trace: demo-trace`, despite its presence in `ignoreHeaders`. Treat recordings and console logs as data from the traffic. An inferred contract needs review; observing one exchange does not establish the complete API contract.

Stop the proxy with Ctrl+C before trying another listener variant. Normal shutdown also requests recording generation. Keep the target running until finished.

The same request reaches the target and returns the correct response. Dumping produces no recorded examples or contract, with `No stubs were recorded. No contract will be written.` after processing. This disables recording, **not console logging**. It is not a promise that request/response data never appears in logs.

## Understand the proxy list

The released CLI selects **only the first proxy** in `proxies`. A second list entry does not start a second listener.

<details>
<summary>Complete two-entry example</summary>

<CodeBlock language="shell">{require('./includes/proxy/two-proxies.sh?raw').trimEnd()}</CodeBlock>

</details>

Return to [configuration tasks](/references/configuration), find proxy fields in the [explorer](/references/configuration/explorer), or read [all keys](/references/configuration/all-keys). This recipe checks local HTTP forwarding and recording; TLS/client certificates, adapters, mock-backed interception, other entry points and broader path layouts need separate verification. The forward proxy's CONNECT method is unsupported in the reviewed runtime; do not use this setup as an HTTPS tunneling proxy.
