# Configure SOAP with WSDL

Use `runOptions.wsdl` to mock a SOAP service or test its running implementation. These complete V3 examples exercise a local SOAP 1.1 contract in OSS and Enterprise.

## Save the inputs

Follow the [Docker setup](/references/configuration/local-openapi#docker-setup). Save the files below in one folder and run commands there. Use Bash-compatible commands; the optional demo needs Node.js 20+. Keep ports **9100**, **9101** and **9102** free. The relative-path troubleshooting example additionally uses **9000**.

The source directory uses a configuration template. Each command supplies its mounted container path, `/usr/src/app`, through `SOAP_SPEC_DIRECTORY`; this avoids the released WSDL mock path-matching issue described below. `CONFIG_FILE_PATH` selects the named configuration at process startup. With your final file named `specmatic.yaml`, ordinary config discovery also applies.

## Fix a relative-path mock endpoint

In OSS 2.55.3 and Enterprise 1.28.3, this local WSDL mock can miss its configured endpoint when the specification source remains relative. The WSDL feature records an absolute path while the endpoint lookup retains a relative path. This is a released mock-routing limitation, not a rule that WSDL always ignores its run options.

With no `SOAP_SPEC_DIRECTORY` supplied, the directory template in `mock.yaml` falls back to `.`. Run this in a fresh terminal without that variable:

<CodeBlock language="shell">{require('./includes/wsdl/mock-relative.sh?raw').trimEnd()}</CodeBlock>

Expected excerpt:

<CodeBlock language="terminaloutput">{require('./includes/wsdl/mock-relative.terminaloutput?raw').trimEnd()}</CodeBlock>

The mock starts at `0.0.0.0:9000`, despite the configured 9101. Stop it with Ctrl+C. The primary command above supplies the absolute source directory and restores configured routing. Alternatively, for this single-listener setup, choose the fallback listener through CLI options:

<CodeBlock language="shell">{require('./includes/wsdl/mock-relative-cli.sh?raw').trimEnd()}</CodeBlock>

Expected excerpt:

<CodeBlock language="terminaloutput">{require('./includes/wsdl/mock-relative-cli.terminaloutput?raw').trimEnd()}</CodeBlock>

That recovery listens on 9101. It does not establish that CLI options reproduce multiple per-spec endpoints; use the absolute-directory command for the override examples.

## Scope of these examples

Verified against OSS **2.55.3** and Enterprise **1.28.3**: local SOAP 1.1 mocking/testing, explicit examples, endpoint precedence, matching per-spec overrides, generated SOAPAction quoting and wrong-mode validation. The commands use the same files as the documentation checks. These examples do not establish HTTPS/mTLS, imported WSDL/XSD resolution, SOAP 1.2 or other integration behavior.
