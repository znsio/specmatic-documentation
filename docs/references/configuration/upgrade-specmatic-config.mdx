# Upgrade Older Configuration to V3

Use `config upgrade` with an explicit input and a separate output. Keep the original until you have compared the configurations' behavior. The [complete migration journey](./migrating-config-v2-to-v3) supplies both files, specifications, test/mock commands and expected outcomes.

With that journey's files, run:

<CodeBlock language="shell">{require('./includes/migration/upgrade.sh?raw').trimEnd()}</CodeBlock>
<CodeBlock language="terminaloutput">{require('./includes/migration/upgrade.terminaloutput?raw').trimEnd()}</CodeBlock>

`--input` selects the existing file. `--output` writes YAML to the supplied path, regardless of its extension; choose a `.yaml` filename. An existing output can be overwritten. The first line above prevents that in the demonstration.

Without `--input`, the command uses [normal config discovery](./files-and-paths). Without `--output`, it logs the converted YAML to the terminal; this does not create a file. Avoid treating the entire terminal transcript as a config because release banners or warnings may also appear.

An already-V3 input exits successfully with an up-to-date message and does not write a requested output. Missing files, invalid versions or binding errors fail; correct the original input before retrying. Conversion does not automatically establish runtime equivalence: validate the output and compare the tests, mock responses, targets and reports you rely on.
