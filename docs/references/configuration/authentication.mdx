# Configure OpenAPI authentication

Put credentials in a **matching per-spec run-option entry**. Two names must line up: the spec `id` identifies the contract, and each `securitySchemes` map key identifies a scheme in that contract's `components.securitySchemes`.

This V3 recipe checks **OSS 2.55.3** and **Enterprise 1.28.3** against an independent local service. It covers bearer, OAuth2, OpenID Connect, Basic, header API keys and query API keys, plus an unauthenticated operation. It supplies tokens; it does not demonstrate token issuance, login or refreshing an expired token.

| Config `type` | Supply in `token` | Request sent |
|---|---|---|
| `bearer`, `oauth2`, `openIdConnect` | Raw token, without `Bearer ` | `Authorization: Bearer <token>` |
| `basicAuth` | Base64 of `username:password`, without `Basic ` | `Authorization: Basic <token>` |
| `apiKey` | Raw key | Header or query parameter selected by the OpenAPI scheme's `in` and `name` |

The example uses public demo credentials. For a real endpoint, use [HTTPS](/references/configuration/https) and a [config template](/references/configuration/template-values) such as `token: '{API_TOKEN:}'` with the variable supplied by your environment. Test request logs and reports can contain credentials; do not share them as sanitized output.

## Choose where the credential comes from

For these core HTTP consumers, lookup is:

1. A nonblank token from the matching config entry, with a compatible credential type.
2. The environment variable named exactly after the OpenAPI scheme, then a Java property of that name.
3. For bearer/OAuth/OIDC, `SPECMATIC_OAUTH2_TOKEN`; for Basic, `SPECMATIC_BASIC_AUTH_TOKEN` (environment before Java property).
4. Without a supplied credential, request generation can use dictionary/generated values. A generated value is not an issued credential.

Config-template resolution happens before this lookup. It uses the variable named inside the template, which can differ from the scheme name. Example-level headers and dictionary selection have additional consumers; this recipe establishes the cases below, not a universal precedence rule for every authored example.
