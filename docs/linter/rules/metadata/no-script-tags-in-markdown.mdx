# `no-script-tags-in-markdown`

Finds `<script` text in textual title and description fields.

| Attribute | Value |
|---|---|
| Category | Metadata |
| Maturity | Platinum |
| OpenAPI | Swagger 2.0; OpenAPI 3.0, 3.1, 3.2 |
| Starter | Off |
| Lenient–Strict | Warning |
| Complete | Error |

## Intent

Script elements embedded in rendered documentation can become a cross-site scripting path in unsafe consumers.

## Flags

Any textual field named `title` or `description`, anywhere in the document, containing `<script` in any letter case.

## Does not flag

Other field names or non-string values. This targeted substring check does not sanitize every unsafe HTML construct.

## See it fail

```yaml
info:
  title: Payments API
  description: "<script>alert('unsafe')</script>"
```

Diagnostic: ``Markdown fields must not include `<script` tags.``

## Fix it

Remove the script content and keep documentation descriptive:

```yaml
info:
  title: Payments API
  description: Creates and retrieves payments.
```

## Configure

```yaml
profiles:
  default:
    rules:
      extends: [recommended]
      override:
        no-script-tags-in-markdown: error
```
